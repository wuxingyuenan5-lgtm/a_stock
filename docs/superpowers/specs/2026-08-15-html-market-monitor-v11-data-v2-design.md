# A股每日市场监控｜HTML v1.1 + Canonical 数据母表 v2 设计

## 1. 目标

在 HTML v1 已经实现单文件离线展示、动态百亿成交明细、申万行业与拥挤度模块的基础上，进一步解决两类问题：

1. **展示交互不足**：时间序列无法拖动筛选、申万行业缺少三态排序、05/06 图表表达不够清晰、百亿成交矩阵方向与展示窗口不符合日常使用习惯。
2. **数据母表风险**：当前 CSV 既承担长期历史存储又直接驱动 report_data.json，一旦 CSV 被错误覆盖或写入异常值，HTML 会稳定展示错误数据。

本版将展示层升级为 HTML v1.1，同时把数据链升级为：

```text
Raw 原始采集
→ Canonical 已验证历史母表
→ Canonical Validator + manifest
→ report_data.json
→ HTML Renderer
→ HTML Validator
→ HTML 成品
```

CSV 继续作为 GitHub 中的长期可审计历史载体，不引入 SQLite；但不再允许“采集结果直接等于正式历史”。

---

## 2. 时间序列图统一交互合同

### 2.1 适用范围

所有按日期变化的图统一支持时间滚轴，包括：

- 市场涨跌结构；
- 市场宽度；
- 05 申万四行业资金拥挤度全部时间图；
- 06 创新药交易拥挤度全部时间图；
- 后续新增的任何时间序列图。

非时间序列表格不需要时间滚轴。

### 2.2 默认行为

用户选择 **C：默认展示全历史**。

页面首次打开时：

- 图表主视图显示全部可用历史；
- 底部时间滚轴覆盖全部历史范围；
- 用户可以拖动左边界、右边界或整个已选区间；
- 主图根据所选区间重新计算 x/y 轴显示范围，而不是仅做视觉裁剪；
- 双击或点击“全部”恢复全历史。

### 2.3 交互图表实现

HTML 仍必须是**单文件、自包含、离线可打开**。

允许使用成熟图表引擎，但其运行代码必须打包/内嵌进最终 HTML，不允许 CDN、外部 JS、外部 CSS 或运行时网络依赖。

统一要求：

- tooltip 显示日期、指标名、真实值与单位；
- 图例明确可见，并允许点击隐藏/恢复序列；
- 左/右轴必须有指标名称和单位；
- 最右侧日期、右轴、图例不得重叠；
- 最新数据点必须进入全历史数据集；
- 时间滚轴筛选后 tooltip、面积、折线和坐标轴同步变化。

## 3. 01｜申万行业交互升级

### 3.1 保留功能

继续保留：

- 文本搜索；
- 一级/二级行业筛选；
- 最新有效日期显示；
- 完整一级/二级行业列表。

### 3.2 三态排序

以下三列支持独立排序：

- 成交额；
- 日收益率；
- 20日年化波动率。

每列点击状态循环：

```text
原始顺序 → 降序 → 升序 → 原始顺序
```

要求：

- 任一时刻只保留一个主排序字段；
- “原始顺序”必须恢复 `sw_industry_latest.csv` / Canonical 申万快照的原始业务顺序；
- 恢复原样不得按名称、代码或当前 DOM 顺序重新排序；
- 搜索和层级筛选与排序可以叠加使用；
- 清空筛选后仍保留当前排序状态，直到用户恢复原始顺序。

## 4. 04｜百亿成交展示与历史存储

### 4.1 Canonical 历史

`hot_stocks.csv` 的正式 Canonical 版本必须保存**全部已验证历史明细**，不因为 HTML 只显示最近若干日而截断数据。

主键：

```text
(date, stock_code)
```

同日重跑规则：

- 当天数据可以整日重建；
- 其他历史日期不得被删除；
- 空值不得覆盖同主键已验证非空值；
- 每次历史修改必须在 manifest 中记录被修改日期与行数。

### 4.2 最近日期矩阵

HTML 默认展示**最近 10 个有百亿成交记录的交易日**。

方向固定为：

```text
最新日期 | 次新日期 | ... | 最早日期
```

即最新日期在最左侧，历史向右延伸。

矩阵显示窗口只是展示行为；CSV/Canonical 层必须保存全部历史。

矩阵行业口径继续沿用现有申万二级归类逻辑；超出主行业显示容量的仍归入“其他行业汇总”。

### 4.3 最新日完整个股明细

继续完整展示报告日全部百亿成交股，不设 7 行、10 行或其他固定上限。

## 5. 05｜申万四行业资金拥挤度

### 5.1 页面内容

保留四行业最新官方有效日及四行业核心数据：

- 通信设备；
- 计算机设备；
- 元件；
- 半导体。

每个行业显示：

- 成交额占全A；
- 换手率；
- 如需要可在摘要卡显示成交额，但 HTML 不再展示“四行业成交额合计”表。

### 5.2 图表

“成交额占全A”不再使用普通折线，而使用**面积图**。

建议拆为两张图，避免双轴过载：

1. **四行业成交额占全A**：面积图；
2. **四行业换手率**：折线图。

每张图必须：

- 有标题；
- 有图例；
- y 轴写明指标和单位 `%`；
- tooltip 写明日期、行业、数值；
- 带时间滚轴，默认全历史；
- 图例颜色与 tooltip 文案一一对应。

四行业成交额合计历史图和 HTML 表格均删除，不作为日常展示重点。

## 6. 06｜创新药交易拥挤度

页面继续只保留真实业务字段：

- 成交额；
- 成交额占全A；
- 供应商直接板块换手率；
- 日收益率；
- 成交量。

永久禁止“20日成交量活跃度代理”重新进入 Canonical、report_data 或 HTML。

图表拆为：

1. **创新药成交额占全A**：面积图；
2. **创新药换手率**：折线图。

要求与 05 一致：标题、图例、单位、tooltip、时间滚轴全部明确；默认全历史。

如果某日成交额占比缺失但同日创新药成交额和同日全A成交额均存在，Canonical Validator 必须先恢复该值，不能把可恢复空值留给 HTML。

## 7. Canonical 数据母表 v2

### 7.1 分层

数据层明确分为：

#### Raw

保存采集程序的直接结果，可包含：

- 接口状态；
- 原始值；
- 抓取时间；
- 数据源；
- 异常/失败信息。

Raw 不直接驱动 HTML。

#### Canonical

只保存通过数据合同和质量检查的正式历史值。

当前继续使用 GitHub CSV，至少包括：

- `market_core.csv`；
- `indices_history.csv`；
- `hot_stocks.csv`；
- `sw_industry_history.csv` / 最新快照；
- `sw_analysis_daily_second.csv`；
- `innovation_drug_eastmoney.csv`。

`report_data.json` 只允许读取 Canonical，不读取 Raw。

### 7.2 Canonical 写入规则

所有历史表统一执行：

- 主键唯一；
- 日期格式合法；
- 数值字段类型合法；
- 同日重跑空值不得覆盖已验证非空值；
- 历史非当天记录发生变化必须可追踪；
- 大规模历史删除、日期回退或行数异常减少直接 FAIL；
- 来源字段与采集/验证时间必须保留；
- 可数学复核的派生字段必须重新计算并比对。

### 7.3 数据合理性检查

不仅检查“是否为数字”，还增加跨字段/跨日规则。

示例：

- `advance + decline + flat == effective_stocks`；
- `market_breadth == (advance - decline) / (advance + decline)`，容差内一致；
- `hot_concentration == hot_amount_100m / total_amount_100m`；
- 百亿股明细行数 == `hot_count`；
- 百亿股明细成交额合计 == `hot_amount_100m`，容差内一致；
- 创新药成交额占比 == 创新药成交额 / 同日全A成交额；
- 四行业成交额占比与同日全A分母、派生成交额一致；
- 指数同日 return/amount/close 的来源状态必须匹配；
- 最新日期不得倒退；
- 历史行数不得无解释大幅减少。

### 7.4 异常跳变

对可能出现录入/单位错误的字段增加异常跳变规则。

异常跳变不是自动否定市场真实极端行情，而是：

- 触发 WARN；
- 与来源/同日其他字段交叉验证；
- 无法确认时阻止其覆盖既有 Canonical 历史。

例如全A成交额若从约 2 万亿元突变为约 2 千亿元，需要先检查是否单位少一位、接口口径变化或抓取失败。

## 8. Canonical manifest

每天生成：

`canonical_manifest_YYYY-MM-DD.json`

至少记录：

- schema/version；
- 每个 Canonical CSV 的 SHA256；
- 总行数；
- 最新日期；
- 最早日期；
- 主键重复数；
- 关键字段缺失数；
- 本次新增日期；
- 本次修改的历史日期；
- 被拒绝的 Raw 更新；
- WARN/FAIL 项；
- 数据源与验证时间。

manifest 与 Canonical CSV 一起归档，作为“这一天 HTML 为什么显示这些数据”的审计依据。

---

## 9. 生产顺序

正式每日链路升级为：

```text
1. 读取上一版 Canonical + manifest
2. 历史完整性扫描
3. 对可恢复缺口执行定点回填
4. 抓取当日 Raw 数据
5. Raw → Candidate Canonical
6. Canonical Validator
7. 通过后原子写入 Canonical CSV
8. 生成 canonical_manifest
9. Canonical → report_data.json
10. HTML Renderer
11. HTML Validator
12. 上传单一生产 artifact
13. 归档 HTML + report_data + manifest + validation
```

如果 Canonical Validator FAIL：

- 不更新正式历史；
- 不生成可交付 HTML；
- 保留 Raw 与失败报告供排查。

如果只是无法自动修复的历史源缺口且不破坏当日核心数据，则可以 WARN，但必须在质量区明确显示。

## 10. HTML Validator v1.1

除 v1 已有检查外，新增：

- 所有时间图必须存在时间滚轴配置；
- 默认滚轴范围必须为全历史；
- 01 三个可排序字段必须具备原始/降序/升序三态；
- 04 矩阵必须最多默认展示近10个日期且最新日期在左；
- `hot_stocks.csv` Canonical 历史不得被 Renderer 截断；
- 05 成交额占全A必须为面积图；
- 06 成交额占全A必须为面积图；
- 05 不得出现“四行业成交额合计”HTML 表；
- 20日成交量活跃度代理不得出现；
- HTML 仍不得存在外部网络依赖。

## 11. 本轮验收标准

以 2026-08-14 原型为回归基准：

1. 所有时间图打开时展示全历史，并可拖动时间滚轴筛选；
2. 市场结构图最新仍为 8/14；
3. 01 的成交额、日收益率、20日年化波动率三列三态排序正确；
4. 04 默认展示最近10个有记录交易日，8/14 位于最左列；
5. Canonical 百亿成交 CSV 保留全部已验证历史，不只10日；
6. 05 成交额占比为面积图，换手率图图例/单位/tooltip 清晰，不显示四行业成交额合计表；
7. 06 成交额占比为面积图，换手率为真实供应商字段；
8. 所有图表有标题、图例、单位和 tooltip；
9. canonical manifest 能列出每个数据文件的 SHA、行数、最新日期和历史修改记录；
10. Canonical Validator 能主动拦截一个人为制造的单位错误/历史覆盖错误测试样本；
11. HTML 仍为单文件离线成品；
12. 全套 CI 通过后才允许 PR #34 从 Draft 转正式评审。

---

## 12. 明确不做

本轮不引入：

- SQLite / PostgreSQL；
- 前端服务器；
- CDN；
- 多用户状态保存；
- 复杂数据库迁移；
- Excel Dashboard 继续扩展。

目标是保持 GitHub + CSV + JSON + 单文件 HTML 的低运维结构，同时把数据可信度和展示交互提升到可长期每日使用的水平。
