# A股每日市场监控 HTML 主展示设计

## 目标

把《A股每日市场监控》的正式展示层从复杂 Excel 仪表盘迁移为独立 HTML，同时保留结构化数据层和可选的简化 Excel 数据底表。HTML 负责每天阅读、图表和动态表格；GitHub 数据层负责抓取、历史补缺、校验和归档。

## 核心原则

1. HTML 不再依赖 Excel 固定行号、图表对象、隐藏辅助区域或样式复制。
2. 所有展示模块只读取同一份标准化生产数据，不允许首页和明细页分别维护两套逻辑。
3. 每日生产先执行历史完整性预检，再处理当天数据；可自动恢复的历史缺口必须先补齐。
4. 缺失数据不得以 0、代理指标或跨口径值伪填；无法修复时必须在数据质量区明确列出。
5. HTML 必须是单文件、自包含，可直接双击打开；不依赖 CDN、服务器或外部 JS/CSS。
6. 表格高度和模块位置由实际记录数决定，不存在固定“第 N 行开始”的布局合同。

## 生产架构

正式链路：

GitHub 数据采集 → 历史缺口预检/定点回填 → 标准化 report_data.json → HTML Renderer → HTML Validator → HTML 成品 → GitHub 归档。

Excel 不再作为 HTML 的中间母表。后续如保留 Excel，则由同一份 report_data.json 生成简化数据底表，仅承担筛选、公式和二次分析，不承担复杂 Dashboard。

## 数据预检与历史回填

每天正式生产前扫描关键历史字段：

- 上证50、Choice微盘、中证全指：收盘价、涨跌幅、成交额。
- 全A：成交额、上涨/下跌/平盘家数、涨停/跌停家数、市场宽度。
- 百亿成交：每日个股数量、成交额、完整明细。
- 申万行业：一级/二级行业最新有效快照。
- 四行业拥挤度：通信设备、计算机设备、元件、半导体的成交额占比和换手率。
- 创新药：成交额、成交额占全A、供应商直接板块换手率。

回填规则：

- 历史指数缺口走历史 K 线接口，不允许使用当前报价倒填。
- 创新药成交额占比缺失时，只允许用“同日创新药成交额 / 同日全A成交额”恢复。
- 创新药换手率只接受供应商直接板块换手率，不允许代理或倒算。
- 同一字段已有已验证非空历史值时，新的空值不得覆盖。
- 自动回填失败则生成明确 WARN/FAIL，并在 HTML 数据质量区列出日期、字段、原因。

本次 8/14 原型必须优先补：

- 2026-08-13 上证50、Choice微盘、中证全指三项历史缺口。
- 2026-08-07 全A成交额分母，从而补创新药成交额占比。

## HTML 页面结构

### 1. 页首

- 报告名：A股每日市场监控。
- 报告日期。
- 数据截止时间。
- 数据完整性状态：PASS / WARN / FAIL。

### 2. 市场总览 KPI

固定展示但不固定像素宽度：

- 上证50涨跌幅。
- Choice微盘涨跌幅。
- 中证全指涨跌幅。
- 全A成交额。
- 百亿成交股数。
- 市场宽度。

### 3. 市场涨跌结构

一张组合图：

- 上涨家数：正柱。
- 下跌家数：负柱。
- 涨停家数：右轴正线。
- 跌停家数：右轴负线。

要求：

- 图表数据直接来自完整历史数组，最新有效日必须等于报告日期。
- x 轴左右留出安全边距，最后日期不得与右轴刻度重叠。
- 支持 tooltip 查看真实日期和数值。
- 不存在 Excel 图表 range 扩展问题。

### 4. 市场宽度

独立折线图，显示完整历史市场宽度；0 轴明确。

### 5. 最近交易日指数与成交

展示最近 5 个交易日：

- 三项指数涨跌幅。
- 三项指数成交额。
- 全A成交额。
- 数据状态。

### 6. 申万行业

- 展示最新有效日。
- 一级/二级行业完整表。
- 支持搜索、排序和层级筛选。
- 日常生产只要申万批量快照成功，HTML 必须同步最新有效日，否则 Validator 报错。

### 7. 百亿成交

先展示“最近日期矩阵”，再展示最新日期的完整个股明细。

矩阵：

- 最近 6 个交易日。
- 行业维度与 `04_百亿成交历史` 现有口径一致。
- 超过展示容量的行业使用“其他行业汇总”。

完整明细：

- 当日有 7、12、23、30 只都完整展示。
- 不设置最大 7 行限制。
- 字段：排名、代码、名称、收盘价、涨跌幅、成交额、申万一级、申万二级。

### 8. 申万四行业资金拥挤度

显示最新官方有效日，并展示：

- 通信设备：成交额、占全A、换手率。
- 计算机设备：成交额、占全A、换手率。
- 元件：成交额、占全A、换手率。
- 半导体：成交额、占全A、换手率。
- 四行业合计成交额、占全A。

附历史图表：

- 通信设备成交额占全A。
- 通信设备换手率。
- 四行业成交额合计。
- 四行业成交额占全A。

如果申万官方只更新到 T-1，必须明确显示“最新官方有效日”，不能误标为当日报告日。

### 9. 创新药交易拥挤度

作为正式第 06 模块，不再保留旧的综合拥挤度辅助模块。

只保留：

- 成交额。
- 成交额占全A。
- 可靠板块换手率。
- 日收益率。
- 成交量。

图表：成交额占全A + 可靠换手率。

“20日成交量活跃度代理”永久停用，不进入生产数据、HTML 或 Excel。

### 10. 数据质量

统一列出：

- 每个模块最新有效日。
- 数据源。
- PASS/WARN/FAIL。
- 历史缺口回填结果。
- 仍无法修复的日期和字段。

## 视觉与交互

- 延续当前深蓝标题体系，但减少 Excel 式粗边框。
- 以白底卡片和紧凑表格为主，适合桌面阅读。
- 涨/跌颜色保持现有习惯：上涨/涨停偏暖色，下跌/跌停偏绿色。
- 所有图表为原生 SVG/Canvas JavaScript 渲染，代码直接嵌入 HTML，不引用外部 CDN。
- 页面宽度自适应；桌面优先，缩窄窗口时表格允许横向滚动。
- 表格行数动态增长，模块自然向下排，不使用绝对定位。

## 数据合同

新增标准化 `report_data.json`，至少包含：

- `meta`
- `market_history`
- `indices_history`
- `sw_industry_latest`
- `hot_stock_matrix`
- `hot_stocks_latest`
- `sw_crowding_history`
- `innovation_history`
- `quality`

HTML Renderer 只消费该合同，不重新抓数据、不重新计算业务口径。

## Validator

HTML 交付前必须验证：

1. 报告日期与 market_history 最新日一致。
2. 市场结构图四条序列最新日一致。
3. 最新百亿成交明细行数 = 当日 hot_count。
4. 最近日期矩阵当日合计 = 当日 hot_count。
5. 申万行业最新有效日与生产数据一致。
6. 四行业拥挤度显示的有效日与官方数据一致。
7. 创新药换手率无代理字段。
8. `report_data.json` 中历史关键字段不存在可恢复却仍空白的缺口。
9. HTML 不包含外部 CDN 依赖。
10. HTML 中不存在固定限制百亿明细为 7 行的逻辑。

## 8/14 原型验收

第一版 HTML 以 2026-08-14 为报告日，必须做到：

- 修复 8/13 三项指数历史缺口。
- 修复 8/7 创新药成交额占比分母缺口。
- 市场涨跌结构与涨跌停都显示到 8/14。
- 百亿成交 8/14 的 12 只全部展示；历史日期 8/13 的 23 只不受固定行数限制。
- 申万行业显示实际最新有效日。
- 四行业拥挤度显示实际最新官方有效日。
- 创新药只有真实换手率，无活跃度代理。
- 页面无坐标轴与最后日期重叠。
- 单文件离线可打开。

## Excel 后续定位

本阶段先完成 HTML 主展示。Excel 暂保留当前版本作为历史参考，不继续投入复杂 Dashboard 修补。HTML 稳定后再决定是否新增“简化 Excel 数据底表”；如新增，必须由同一份 report_data.json 生成，不再反向从 Excel 驱动 HTML。
